# CSP43 考场提分参考手册

> 适用对象：第1、2题通常能拿满分，但第3～5题缺少稳定得分方法的 C++ 考生。  
> 目标：把已有的 200 分，升级为“第3题高分 + 第4、5题可靠部分分”，冲击 350～420 分。  
> 使用原则：这不是算法百科；只保留考场里能帮助你识别题型、写出部分分、减少 WA/TLE 的内容。

> **合规提醒**：是否允许携带纸质资料，以准考证、认证点通知和现场要求为准。不要因为有这份资料就默认可以带入考场。

## 0. 先记住：400 分不要求第5题满分

### 三种可行的得分结构

| 方案 | 第1题 | 第2题 | 第3题 | 第4题 | 第5题 | 总分 |
|---|---:|---:|---:|---:|---:|---:|
| 主方案 | 100 | 100 | 100 | 60 | 40 | 400 |
| 均衡方案 | 100 | 100 | 80 | 80 | 40 | 400 |
| 第3题未满方案 | 100 | 100 | 70 | 80 | 50 | 400 |
| 保底方案 | 100 | 100 | 60 | 40 | 20 | 320 |

你的突破重点不是临时学会最难的第5题，而是：

1. 第1、2题不因低级错误丢分；
2. 第3题从“看不懂长题面”变成至少 60～100 分；
3. 第4、5题把每个子任务当作独立小题，稳定拿 20～80 分。

## 1. 四小时考场流程

### 建议时间轴

| 时间 | 任务 | 离开条件 |
|---|---|---|
| 0～5 分钟 | 检查编译环境、语言标准、输入输出模板 | 模板可编译，确认提交入口和剩余提交次数显示位置 |
| 5～25 分钟 | 第1题 | 样例 + 自造边界通过并提交 |
| 25～60 分钟 | 第2题 | 满分；否则先提交可靠部分分并记录问题 |
| 60～75 分钟 | 快速浏览第3～5题 | 为每题写出：主模型、可做子任务、预期分数、预计耗时 |
| 75～165 分钟 | 主攻第3题 | 至少拿到最容易子任务；优先冲 60～100 分 |
| 165～215 分钟 | 第4、5题中收益更高的一题 | 先拿部分分，再决定是否升级 |
| 215～230 分钟 | 另一道高难题的部分分或回修第2、3题 | 选择单位时间预期分数最高的工作 |
| 230～240 分钟 | 总检查 | 不再大改算法，只修确定的错误 |

### 四个强制止损点

- **第1题超过25分钟**：停止盲调，重新核对公式、舍入、下标、并列规则和输出格式。
- **第2题超过40分钟且没有完整算法**：先写/提交正确朴素版或特殊性质版，再浏览第3～5题。
- **第3题阅读12分钟仍画不出状态表**：立即选择最简单子任务，先写一个可运行版本。
- **第4、5题思考15分钟仍说不清状态、转移或复杂度**：停止押满分，改做部分分。

### 提交管理

- 每次提交前必须本地编译；不要用提交系统替你找编译错误。
- 得到部分分后，立刻保留稳定版本，例如：`t4_40.cpp`、`t4_60.cpp`。
- 优化时复制新文件，不直接覆盖唯一能得分的版本。
- 根据实时分数判断下一步：格式错误/样例错先修；已有可观分数时不要无证明地推翻代码。

## 2. 数据范围 → 复杂度第一判断

> 只是第一判断，最终必须结合时间限制、常数、测试组数和语言。

| 规模 | 首先考虑 |
|---:|---|
| `n <= 20` | 子集枚举、状态压缩 DP、DFS |
| `n <= 40` | 折半搜索、双向枚举 |
| `n <= 200` | `O(n^3)` 可能可行 |
| `n <= 2000` | `O(n^2)` 可能可行 |
| `n <= 2e5` | `O(n log n)` |
| `n <= 1e6` | 线性/近线性 |
| 值域 `<= 512 / 1e4` | 查表、计数、值域 DP、bitset |
| `q` 很大 | 预处理、离线、数据结构；避免每次完整重算 |
| 图是树 | 树 DP、DFS 序、LCA、树上差分；不要套普通图的重算法 |

### 题面关键词速配

| 题面信号 | 第一候选 |
|---|---|
| 最大化最小值、最小化最大值、最大可行/最小可行 | 先证明单调性，再二分答案 |
| 静态区间和/计数 | 前缀和 |
| 多次区间加，最后问点值/整体结果 | 差分 |
| 无权图最少步数 | BFS |
| 非负边权最短路 | Dijkstra |
| 依赖关系、先后顺序 | 拓扑排序 / DAG DP |
| 连通所有点且代价最小 | MST（Kruskal/Prim） |
| 容量、花费、收益、每件选或不选 | 0-1 背包 |
| 同类物品可无限使用 | 完全背包 |
| 多次修改 + 区间查询 | 树状数组/线段树/分块/有序集合 |
| 树上路径查询 | 深度、父亲、LCA、树剖或点分治 |
| 嵌套表达式、协议字段、配置文本 | 栈/递归下降/状态机 |
| 展开结果巨大，但只问长度/哈希/计数 | 不展开；只存摘要 + 记忆化 |
| 子数组 `gcd/and/or` | 扩展端点时不同结果通常很少，可压缩状态 |

## 3. 第1题：100分防丢清单

### 开写前

- 输入是否有负数、零、重复值？
- 是否需要稳定排序或并列时取更小编号？
- 最大乘积是否超过 `int`？`1e9 * 1e9` 必须 `long long`。
- 小数能否改写为整数运算？
- 除法是向下、向上、四舍五入还是“五取偶”？

### 常用安全公式

```cpp
// 仅适用于 a >= 0, b > 0
long long ceil_div(long long a, long long b) {
    return a / b + (a % b != 0);
}

long long norm_mod(long long x, long long mod) {
    x %= mod;
    if (x < 0) x += mod;
    return x;
}
```

### 交卷前五组自测

1. 最小输入；
2. 最大值附近；
3. 全部相等；
4. 刚好落在分界点；
5. 分界点左右各一个值。

## 4. 第2题：从水题升级到基础算法题

近年的第2题可能直接出现 BFS、背包、二分答案、贪心组合。因此读完题后按下面顺序检查。

### 4.1 是否可前缀/差分

```cpp
vector<long long> pre(n + 1);
for (int i = 1; i <= n; ++i) pre[i] = pre[i - 1] + a[i];
// [l, r] 和：pre[r] - pre[l - 1]

vector<long long> diff(n + 3);
diff[l] += v;
diff[r + 1] -= v;
for (int i = 1; i <= n; ++i) diff[i] += diff[i - 1];
```

### 4.2 是否可二分答案

先写一句证明：

```text
当答案 x 可行时，所有更小/更大的值是否必然可行？
```

只有得到连续的 `TTTFFF` 或 `FFFTTT`，才能二分。

```cpp
// 最大的 true：check(x) = true, true, ..., false
long long l = low, r = high;
while (l < r) {
    long long mid = l + (r - l + 1) / 2;
    if (check(mid)) l = mid;
    else r = mid - 1;
}
```

### 4.3 是最少步数吗

- 边权全为1：BFS。
- `visited` 要在入队时标记，而不是出队时。
- 限定 `k` 步时保存距离，不要用普通 DFS + 布尔访问数组。

### 4.4 是背包吗

```cpp
// 0-1背包：容量倒序
for (auto [w, v] : items)
    for (int j = W; j >= w; --j)
        dp[j] = max(dp[j], dp[j - w] + v);

// 完全背包：容量正序
for (auto [w, v] : items)
    for (int j = w; j <= W; ++j)
        dp[j] = max(dp[j], dp[j - w] + v);
```

背包四问：

1. `dp[j]` 到底表示“恰好”还是“不超过”？
2. 初始不可达状态是否应为负无穷？
3. 物品能选几次？
4. 枚举顺序是否正确？

## 5. 第3题：长题面大模拟的固定解法

第3题最常见的失败不是不会算法，而是没有建立清晰的数据模型。

### 5.1 读题后先填这张表

| 项目 | 需要写出的内容 |
|---|---|
| 实体 | 进程、资源、缓存块、文件、用户、消息、矩阵操作…… |
| 主键 | 每个实体如何唯一定位 |
| 可变状态 | 哪些字段会随操作改变 |
| 全局关系 | 占用、依赖、父子、时间顺序、空闲区间 |
| 事件 | 每种输入操作的前置条件、修改和输出 |
| 不变量 | 任意时刻都必须成立的性质 |

### 5.2 固定执行顺序

```text
读取并解析
→ 检查前置条件
→ 找到目标对象/资源
→ 修改状态
→ 产生输出
→ 释放、合并、过期或清理
```

同一时刻有多个事件时，明确优先级；不要依赖输入顺序猜测。

### 5.3 推荐代码骨架

```cpp
struct Object {
    int id;
    // 只放对象自己的状态
};

struct SystemState {
    vector<Object> obj;
    // 全局索引、资源集合、时间等
};

void parse_input(SystemState& s);
void handle_new(SystemState& s, /* args */);
void handle_delete(SystemState& s, /* args */);
void handle_query(SystemState& s, /* args */);

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    SystemState s;
    parse_input(s);
    // 主循环只负责分派，不堆业务细节
}
```

### 5.4 字符串解析三条铁律

```cpp
int n;
cin >> n;
cin.ignore(numeric_limits<streamsize>::max(), '\n');
string line;
getline(cin, line);
```

- 混用 `cin >>` 与 `getline` 时清掉整行剩余字符。
- 嵌套括号使用栈或递归下降，不要靠大量 `find/substr` 拼补。
- 十六进制、转义、字节序先单独写转换函数并测试。

### 5.5 不要真的展开巨大对象

当字符串/模板可能指数膨胀，而题目只问长度、哈希或计数：

```text
表达式保存为 DAG/引用列表
→ 每个节点只存长度、哈希或统计量
→ 单次查询使用记忆化
→ 每次修改后只失效受影响节点
```

### 5.6 区间分配/释放

- 空闲区间保持有序、互不相交。
- 释放后检查左右相邻区间并合并。
- `first-fit`、`best-fit`、`最小起点优先`含义不同，必须按题意。
- 为部分分可先线性扫描空闲区间；满分再换双索引结构。

### 5.7 缓存/LRU/过期事件

使用优先队列懒删除时，每条记录带时间戳或版本号：

```cpp
while (!pq.empty() && pq.top().version != current[pq.top().id]) {
    pq.pop();
}
```

否则旧记录会把已经更新过的对象错误删除。

### 5.8 大模拟调试法

- 每完成一个操作函数，就用只含该操作的最小样例测试。
- 写 `check_invariant()`：空闲区间是否相交、数量是否一致、引用是否存在。
- 在 `#ifdef LOCAL` 下打印关键状态；提交前自动关闭。
- 比较“每一步状态”，不要只看最终输出。

## 6. 第4、5题：部分分作战手册

### 6.1 先读子任务，不先读故事

为每个子任务记四项：

```text
分值 | 额外限制 | 可用算法 | 预计代码时间
```

优先做“分值 / 时间”最高的子任务。

### 6.2 高频部分分入口

| 特殊限制 | 常见做法 |
|---|---|
| `n <= 20` | 暴力 DFS、子集枚举、状态压缩 |
| `n <= 40` | 折半搜索 |
| 图是树 | DFS、树 DP、LCA、树上差分 |
| 图是链 | 前缀、双指针、线性 DP |
| 没有修改 | 离线排序、一次预处理 |
| 只有增加，没有删除 | 简化状态维护 |
| 查询很少 | 每次 BFS/Dijkstra/枚举 |
| 值域很小 | 计数数组、bitset、预处理表 |
| 字符串不嵌套/长度小 | 直接展开模拟 |
| 操作次数小 | 朴素数据结构 |

### 6.3 正确的部分分程序

```cpp
if (n <= 20) {
    solve_bruteforce();
} else if (is_chain()) {
    solve_chain();
} else {
    solve_general_or_slow_but_correct();
}
```

宁可让大数据 TLE，也不要对大数据输出无依据的答案。正确但慢能拿小数据分；随机输出通常一分没有。

### 6.4 第4题识别顺序

1. 图还是数组/区间？
2. 静态还是动态？
3. 能否离线？
4. 树上问题能否用 DFS 序变成区间？
5. 状态数是否很小？
6. 某个运算随区间扩展是否只有少量不同结果？
7. 暴力复杂度能覆盖多少子任务？

### 6.5 第5题决策规则

只有同时满足以下三条，才冲完整高级算法：

- 能明确说出状态/数据结构维护的信息；
- 能解释合并、转移或更新为什么正确；
- 能算出满足限制的复杂度。

缺一条就先写部分分。不要因为题名像“树题”就临时硬写不会的 LCT、点分治或复杂自动机。

## 7. 常见算法的一句话正确性检查

### 二分答案

- `check` 是否真的单调？
- 搜索的是最大 true 还是最小 true？
- `mid` 是否会死循环？
- 上界是否一定覆盖答案？

### BFS / Dijkstra

- BFS：入队即标记。
- Dijkstra：边权必须非负；弹出旧距离时跳过。

```cpp
if (d != dist[u]) continue;
```

### 并查集 / MST

- 合并前比较根。
- MST 最后确认用了 `n-1` 条边；图可能不连通。

### 拓扑排序

- 入度为0才入队。
- 最后处理节点数小于 `n` 表示有环。

### 动态规划

在纸上写清四句话：

```text
状态含义：
初始化：
转移来源：
枚举顺序：
```

写不清这四句，代码大概率会错。

### 线段树

- 区间是 `[l,r]` 还是半开区间？
- lazy 标记是覆盖、加法还是翻转？
- 覆盖与加法同时存在时，组合顺序是否正确？
- 查询前是否 `push_down`？

## 8. 快速对拍与自造数据

### 五类必造数据

1. 最小规模；
2. 全相同/全为0；
3. 严格递增/严格递减；
4. 答案刚好位于边界；
5. 多个操作互相抵消、删除后再添加、同一对象重复出现。

### 有暴力和优化时

```cpp
#ifdef LOCAL
for (int tc = 1; tc <= 10000; ++tc) {
    auto data = random_case();
    auto a = brute(data);
    auto b = solve(data);
    if (a != b) {
        print_case(data);
        cerr << "brute=" << a << " solve=" << b << '\n';
        break;
    }
}
#endif
```

随机数据要小，保证暴力能跑。找到反例后立即固定下来，不要只看随机编号。

## 9. C++ 高频坑

### 整型与溢出

```cpp
long long x = 1LL * a * b;
__int128 y = (__int128)a * b * c;
```

- `vector<int>` 中的两个 `int` 先相乘再赋给 `long long`，仍可能已经溢出；至少一个操作数先转 `1LL`。
- `INF` 不要取到类型极限，避免 `INF + w` 溢出。

### 数组与状态清空

- 多测试组时，局部化数据或明确 `clear/fill`。
- `vector<vector<int>>(n, vector<int>(m))` 下标是 `0..n-1`。
- `erase` 会使后续迭代器/下标失效。

### 递归

- 链状树 `n=2e5` 可能爆栈；可改迭代 DFS，或至少警惕递归深度。
- 记忆化搜索要区分“未计算”和合法答案0。

### 优先队列

- 默认大根堆；小根堆写法：

```cpp
priority_queue<Node, vector<Node>, greater<Node>> pq;
```

- 修改过距离/版本后，旧元素仍在堆中，必须懒删除。

### 输入输出

```cpp
ios::sync_with_stdio(false);
cin.tie(nullptr);
```

不要再混用 `scanf/printf` 与关闭同步后的 `cin/cout`。需要整行时使用 `getline` 并处理残留换行。

## 10. 最后15分钟原则

1. 保存现有可得分版本；
2. 编译所有准备提交的源文件；
3. 每题至少重跑样例和一个最小自造数据；
4. 删除 `freopen`、调试输出、随机测试循环；
5. 检查 `long long`、下标、数组大小、清空、取模和换行；
6. 查看每题当前得分与提交状态；
7. 不在最后15分钟无证明地重写一整套算法；
8. 若有一题未提交，至少提交能编译、对小数据正确的部分分版本。

完整逐项清单见 `CSP43_最后15分钟自检卡.md`。

## 11. 本手册的最终使用方式

考前练习时，强制按本手册记录：

```text
题目：
数据范围：
主模型：
朴素复杂度：
可做子任务：
目标分：
正确性一句话：
最容易错的边界：
```

考试时真正能提分的，不是看到某个模板名字，而是能快速完成四件事：

1. 用数据范围排除错误复杂度；
2. 用状态表拆开长模拟；
3. 把子任务变成可以提交的独立程序；
4. 在最后阶段保护已经获得的分数。
