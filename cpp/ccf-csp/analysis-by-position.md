## 第1题：稳定的基础实现，但边界陷阱比算法更重要

### 历史画像

- 模型将 **基础实现** 估为 78.7%，其次是 **数学/数论/位运算** 13.1%。
- 常见知识点：计数数组、排序、哈希、矩阵下标、简单贪心、公式、日期时间、整数舍入。
- 近年代表：`202506-1 正态分布` 强调整数化规避浮点误差；`202603-1 平衡数` 是位计数；第42次“银行家舍入”继续考规则与边界。

### 标准做题流程

1. 用一句话重述输入到输出的映射，确认没有隐含状态。
2. 从数据范围判断 `int`、`long long` 或更大类型；涉及小数先问能否整数化。
3. 写最直接的 `O(n)` 或 `O(n log n)` 实现，不做无收益的复杂优化。
4. 手测最小值、最大值、全相等、边界刚好命中、负数/零、奇偶与舍入点。
5. 第一次提交若 WA，优先检查题意分支和格式，而不是推翻算法。

### 易错点

浮点截断、整数除法、1/0 下标、最后一个元素、并列时的次关键字、读入空行、溢出与输出精度。

### 建议训练

先连续刷最近 12 场第1题，要求每题独立完成并一次通过；再补日期、矩阵、哈希计数和舍入类老题。

## 第2题：从“基础实现”向基础算法题迁移

### 历史画像

- 模型前三类：基础实现 41.8%、数学/数论/位运算 19.8%、动态规划 11.4%。
- 常见知识点：前缀和、差分、二分答案、排序扫描、集合、矩阵运算、背包、BFS、贪心。
- 近年变化很明显：`202503-2` 完全背包，`202506-2` BFS，`202603-2` 0-1背包+分数背包，`202605-2` 二分答案。

### 标准做题流程

1. 先写出朴素枚举复杂度；只有超过数据范围才优化。
2. 看到“每个位置/每个询问重复计算一段信息”，优先检查前缀、后缀、差分和离线排序。
3. 看到“最小可行值/最大满足值”，先证明单调性，再二分答案。
4. 看到容量与收益，区分 0-1、完全、多重背包；确认循环方向。
5. 看到最少步数或限定步数可达，优先 BFS，而不是用普通 DFS + `visited`。
6. 保留朴素程序作为小数据对拍器。

### 易错点

二分边界、背包循环方向、差分恢复范围、排序后丢失原下标、把 DFS 误当最短路、重复元素与空集合。

### 建议训练

按“前缀/差分 → 二分答案 → BFS → 贪心 → 0-1/完全背包”顺序建立模板，但每次都先写状态或单调性证明。

## 第3题：最稳定的不是某个算法，而是“大型规则实现”

### 历史画像

- 大模拟/系统 42.7%，字符串/解析 41.3%；两类合计 **84.0%**。
- 常见背景：协议、文件系统、网络服务、编码格式、表达式、配置语言、资源调度、进程与内存。
- 最近连续出现 `HTTP头信息`、`图片解码`、`进程通信`、`死锁优化`，系统化模拟趋势很强。

### 标准做题流程

1. **先画数据模型**：有哪些实体、每个实体有哪些字段、哪些字段会变化。
2. **列事件表**：每种输入操作的前置条件、状态变化、输出和失败分支。
3. 把程序拆成 `parse_*`、`apply_*`、`query_*`，主循环只负责分派。
4. 写并维护不变量，例如“空闲区间不相交且有序”“缓存中同一块只出现一次”。
5. 先通过最简单子任务，再加入嵌套、重复、删除、回滚、异常输入或性能优化。
6. 对拍时比最终输出，也比关键中间状态；大模拟最怕“早一步错、后面全错”。

### C++ 实现要点

- 混用 `cin >>` 与 `getline` 时显式吃掉换行。
- 优先用结构体和枚举表达状态，不用散落的魔法数字。
- 解析嵌套结构时使用栈或递归下降；注意递归深度。
- 避免实际展开指数级字符串；只存长度、引用关系或哈希。
- 需要 LRU/删除旧事件时，可用优先队列懒删除，但必须验证版本号。

### 易错点

状态未清空、同一事件时刻的处理顺序、删除后迭代器失效、行尾空格、十六进制/字节序、重复对象、复杂度隐藏在字符串拷贝或线性查找中。

## 第4题：算法跨度最大，核心能力是建模与部分分设计

### 历史画像

- 模型前三类：数据结构 38.4%、图论/搜索 24.1%、动态规划 14.1%。
- 历史覆盖最短路、MST、网络流、状态压缩DP、区间/树形DP、线段树、分块、计算几何、数论与组合计数。
- 第4题很少能靠“背一个模板”解决，通常需要先把题目转换为熟悉的查询、路径、状态或贡献模型。

### 标准做题流程

1. 用 3～5 分钟只读题和子任务，不立即写代码。
2. 建立复杂度预算：`n<=20` 看状态压缩，`n<=2000` 看平方，`n<=2e5` 看 `n log n`。
3. 将所有操作写成“修改/查询”接口，判断能否离线。
4. 先提交暴力或特殊结构版本拿稳定部分分，并保留它做对拍。
5. 再寻找：
   - 区间贡献是否可前缀化；
   - 值是否只有少量不同状态；
   - 图能否加虚点、拆点或分层；
   - 查询是否可排序后扫描；
   - 树上问题能否用 DFS 序转成区间；
   - `gcd/and/or/xor` 是否随区间扩展只产生少量不同值。
6. 只有在能完整解释正确性和复杂度后，才替换为高级结构。

### 推荐模板优先级

Dijkstra、Kruskal/并查集、拓扑排序、0-1/状态压缩DP、树状数组、懒标记线段树、倍增/LCA、分块、离线排序。

## 第5题：高难综合题，预测最不可靠，得分决策最重要

### 历史画像

- 模型前三类：数据结构 30.8%、图论/搜索 23.5%、动态规划 19.6%。
- 历史高频高级主题包括：线段树、状态压缩DP、网络流、矩阵快速幂、点分治、树形DP、最短路、动态树、字符串自动机。
- 最近第5题依然高度波动：LCT、复杂字符串/组合问题、图与树上的离线统计均出现过。

### 标准做题流程

1. 在确保第1～3题后再完整读第5题；先看子任务分值和约束，不先看长背景。
2. 把每个子任务改写为独立小题，标出能用的算法与预计实现时间。
3. 优先拿以下部分分：
   - `n` 很小：指数搜索/状态压缩；
   - 图是树/链/星形：树DP或前缀；
   - 无修改：离线排序；
   - 值域小：计数/bitset；
   - 查询少：逐查询搜索；
   - 参数固定：降维或枚举参数。
4. 复杂结构只有在“不变量、合并方式、复杂度”都清楚时再写。
5. 场上最后 20～30 分钟不应大规模推翻已能得分的代码。

### 训练方法

每道第5题至少做三层复盘：暴力子任务、一个中档优化、满分思想。即使暂时不会完整实现，也要能说清“为什么朴素超时、结构利用在哪里、部分分能拿多少”。

## 面向 400 分的通用考场顺序

这不是固定时间表，而是风险控制框架：

1. 第1题完成并自测；
2. 第2题完成，保留朴素对拍；
3. 扫描第3～5题全部子任务，标记可得分点；
4. 主攻第3题，把大型模拟做成模块；
5. 在第4题与第5题中选择“单位时间预期得分”更高的一题；
6. 最后统一检查文件、编译选项、整型、空输入、极端数据与已提交版本。

达到 400 分通常不是要求第5题满分，而是要求 **第1、2题稳定满分，第3题尽量高分，第4、5题可靠吃到子任务并至少有一题突破中档**。
